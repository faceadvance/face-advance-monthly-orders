**4) ➕ แยก "🎯 ตรงกัน" ออกจาก "≈ คล้ายกัน <คะแนน>"**
- ปัญหา: ตัวจับ (`detect_customer_duplicates`) ใช้ **ความคล้าย** (trigram) แต่สีในการ์ดใช้ **ตรงเป๊ะ** → **35/205 เคสในคิวไม่มีสีเลย** ทั้งที่เข้าเงื่อนไขถูกต้อง พนักงานไม่รู้ว่าระบบจับที่จุดไหน
- แก้: frontend อ่านฟิลด์ใหม่ `sim` จาก RPC แล้วแยกแสดง
  - `hit:true` → **🎯 ตรงกัน** ป้ายทึบเหลือง (ยืนยันได้)
  - `hit:false, sim:0.60` → **≈ คล้ายกัน 0.60** เส้นประจาง + ป้ายคะแนนต่อท้ายค่า (ยังไม่ยืนยัน)
- ผลวัดจริง: ไม่มีสีเลย **35 → 0** · สีตรงกับ `reason` ที่ทำให้เข้าคิว **81% → 100%** · ไม่มีรายการที่สีหาย (0 regression)
- 🔴 **บทเรียน (พลาด 1 รอบ แล้ว rollback):** รอบแรกลองยัด fuzzy ลงในธง `hit` เลย เพราะคิดว่า "ไม่กระทบ frontend" — **ผิด** เพราะข้อความ `🎯 ตรงกัน` อยู่ใน `edith.ts` แก้จาก backend ไม่ได้ → ป้ายกลายเป็น**ยืนยันสิ่งที่ไม่จริง** (`เอ๋` ⟷ `เอ็ม` คล้าย 0.60 แต่ป้ายบอก "ตรงกัน") ซึ่งอันตรายกว่าไม่มีสี เพราะพนักงานอาจกดรวมตามป้าย · boss จับได้ → rollback ทันที แล้วทำใหม่เป็น **ฟิลด์แยก `sim`** ไม่แตะความหมายของ `hit`
  → **กฎที่ได้: ถ้า frontend เป็นคนตัดสิน "ข้อความ/การตีความ" ห้ามเปลี่ยนความหมายของค่าจากฝั่ง backend เดี่ยวๆ**
