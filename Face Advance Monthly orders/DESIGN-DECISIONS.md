# เว็บแอป Face Advance — สรุปการตัดสินใจดีไซน์ (v1)

> เก็บจาก session brainstorm 2026-08-29..31 · ยังไม่เริ่มเขียนโค้ด · ยังไม่ได้เขียน design spec เต็ม
> mockup ล่าสุด: `webapp/design/mockup-orders-v5.html` (เปิดในเบราว์เซอร์ดูได้)

## เป้าหมาย & สโคป
- เว็บแอปดู + นำเข้าออเดอร์ ให้พนักงานบริษัทใช้ (ต่อยอดจาก database ที่ทำเสร็จแล้ว)
- **v1 (ทำก่อน):** (1) อ่านออเดอร์ (ฟิลเตอร์รายเดือน รวมทุกแบรนด์) (2) นำเข้าออเดอร์ (ใช้ logic เดิม)
- **v2 (ทีหลัง, boss จะบอกอีกที):** ติดตามออเดอร์ = ปรับสถานะหลังนำเข้าให้ complete (งานใหญ่)
- วัตถุประสงค์หลัก = ติดตามแต่ละออเดอร์ (ออเดอร์ไม่ซ้ำ ไม่ใช่ดูยอด/ลูกค้า)

## สถาปัตยกรรม — **แบบ A** (static + Supabase)
- Frontend **static** deploy บน **GitHub Pages** (repo บริษัท) — มีแค่ **anon key** (สาธารณะ ปลอดภัย)
- ตรรกะหนัก (import/audit/อ่านข้อมูล) อยู่ที่ **Supabase** (Postgres RPC + Edge Function)
- **RLS ล็อกแน่น**: ห้ามดึงตารางตรง — อ่านข้อมูลผ่าน **ฟังก์ชันจำกัด** เท่านั้น (เช่น `get_orders(เดือน)`) + log ทุกครั้ง (กันดึงรวดทั้งก้อน)
- **service key ไม่อยู่ใน frontend เด็ดขาด** — อยู่แค่ Supabase
- เว็บหลุดภายนอก = ข้อมูลไม่หลุด (ต้อง login + RLS) · จุดเสี่ยงเดียว = รหัสผ่าน user รั่ว → แก้ด้วยรหัสแข็ง + audit

## Auth — รหัสผ่าน + **LINE OTP (2FA)**
- ผู้ใช้: **user เดียว** (+ boss/ระดับเดียวกันเข้ามาดูได้) สิทธิ์เต็มเหมือนกันหมด ไม่แยกแบรนด์
- **boss สร้างบัญชีเอง ไม่มีระบบสมัคร**
- Flow login: กรอกบัญชี+รหัสผ่าน (Supabase Auth) → ขอ OTP → **Edge Function** สุ่มเลข 6 หลัก เก็บ hash+หมดอายุ(5น.)+จำกัดครั้ง ใน DB → ส่งไป **LINE OA** (channel token ลับใน Edge Function) → user กรอก OTP → verify → ออก session
- เลข OTP ที่ถูก **อยู่แค่เซิร์ฟเวอร์ (hash)** ไม่โผล่ browser
- ต้องเตรียม: LINE OA Messaging API channel token (เก็บลับใน Supabase) + ผูก user ↔ LINE userId (1-3 คน ทำมือ)

## Audit log (boss ต้องการ)
- ทุก login + ทุก action เก็บ: เวลา · IP · อุปกรณ์/เบราว์เซอร์ (user-agent) · บัญชีที่ login · ตำแหน่งโดยประมาณจาก IP (ประเทศ/จังหวัด/เมือง)
- ผูก action กับ session ที่ login → รู้ว่า ใคร/เครื่องไหน/จากไหน/ตอนไหน ทำอะไร
- ทำไม่ได้ = GPS เป๊ะ / ชี้เครื่องชัด 100% (boss รับระดับ IP+เมือง+อุปกรณ์แล้ว)

## หน้านำเข้าไฟล์ (import UX)
- Flow: อัปโหลด xlsx → **pre-flight ตรวจก่อน** (ไม่เข้า DB, แสดงรายงาน: จำนวน/ช่วงวันที่/กรองยกเลิก/ปัญหา/preview ลูกค้าซ้ำ) → **ยืนยัน** → เข้า DB จริง (พร้อมยามทุกชั้น)
- **สินค้าไม่มีใน DB → บล็อกทั้งไฟล์** (ต้องเพิ่มสินค้าก่อน ไม่ให้นำเข้าเลย) — v1 เพิ่มสินค้าผ่าน Supabase dashboard ไปก่อนได้ (หน้าจัดการสินค้าค่อยทำทีหลัง)
- ใช้ pipeline เดิม (`database/seed/import_gosell_orders.py` logic + guards) — ตอน build port เป็น RPC/Edge Function

## ดีไซน์ UI (ดู mockup v5)
- **Light mode เท่านั้น** (ห้าม dark) · จอคอม (desktop)
- **Palette** (จาก research แองจี้): bg #F8FAFC, card #FFF, border #E2E8F0, text #0F172A/#475569/#94A3B8, primary #2563EB. สถานะ badge: success #D1FAE5/#065F46, warning #FEF08A/#854D0E, info #BFDBFE/#1E3A8A, **ตีกลับ=แดงทึบ #DC2626**, **ยกเลิก=เทาเข้มทึบ #475569**
- **Font**: IBM Plex Sans Thai + Inter (ตัวเลข tabular-nums)
- **Icon**: ใช้ **SVG (แนว Lucide) `currentColor`** ทั้งแอป — **ห้าม emoji** (boss สั่ง — ต้องปรับสไตล์ได้)
- **การ์ดสรุปบน = 3 การ์ด** (mockup v6): (1) จำนวนส่งออก (2) ยอดขาย (3) ตีกลับ · แต่ละการ์ด: ไอคอนในวงกลม + ลายจางไอคอนใหญ่มุมขวาบน + ตัวเลขหลัก(ซ้าย) + รายละเอียด(ขวาของตัวเลข เฉพาะยอดขาย/ตีกลับ) + **กราฟแท่งรายวันที่ล่างสุด (ฐานเท่ากันทุกการ์ด)** + caption ใต้กราฟ
  - ส่งออก: แท่งฟ้า · caption "เฉลี่ย X/วัน · สูงสุด Y" · ยอดขาย: แท่งเขียว(ชำระแล้ว)+ส้ม(รอชำระ)ต่อกันในแท่งเดียว · caption "ยอดขายเฉลี่ยต่อวัน ฿X (รวมยอดที่ยังไม่ชำระ)" (=ยอดรวม÷จำนวนวัน) · ตีกลับ: แท่งแดง · ไม่มี caption
  - **กราฟแท่ง: จำนวนแท่ง = จำนวนวันในเดือนที่ดูเสมอ** (1 แท่ง=1วัน ตำแหน่งคงที่) · เดือนปัจจุบันที่ยังไม่ครบ → วันอนาคต = แท่งว่าง(สูง 0) เว้นขวาไว้ เติมเองเมื่อถึงวัน · โลโก้ = `database/Logo/fmark.png` — คอนทราสต์ badge สูง (icon+ตัวหนา+ต่างระดับความสว่าง กันจอไม่ดี/ตาบอดสีแยกไม่ออก)
- **ตาราง**: เรียง **เก่า→ใหม่** (วันที่ 1 อยู่บน) · แบ่งกลุ่มตามวัน · คอลัมน์: เบอร์โทร · ชื่อลูกค้า(**เก็บโค้ดท้ายชื่อไว้** เช่น C209) · ที่อยู่(ตัด ... hover/คลิกดูเต็ม) · ขนส่ง · เลขแทร็ค · ยอดขาย(ชิดขวา) · สถานะจัดส่ง · สถานะชำระ · หมายเหตุ(**= SO20 เท่านั้น หรือว่าง**)
- **Filter แบบ Google Sheets**: ทุกคอลัมน์มีปุ่มกรวย → เรียง ก↔ฮ + ค้นหาค่า + ติ๊กเลือกค่า (เลือกทั้งหมด/ล้าง) · popup เกาะใต้หัวคอลัมน์ · แถบ chip ตัวกรองที่ใช้อยู่ · กรองฝั่ง browser บนข้อมูลเดือนที่โหลดมา
- **ปุ่มซูมในแอป** (A− 100% A+) — ปรับขนาดทั้ง UI ด้วย rem/root (ไม่เพี้ยนเหมือนซูมเบราว์เซอร์) จำค่าให้ user
- **ค้นหา**: เบอร์/ชื่อ/เลขออเดอร์/เลขแทร็ค

## ฟีเจอร์: เลือกเลขแทร็คหลายรายการเพื่อคัดลอก (ล็อกแล้ว 2026-08-31)
- วัตถุประสงค์: เลือกหลายเลขแทร็คแล้วก๊อปทีเดียว (เอาไปวางเช็คสถานะกับขนส่งเป็นล็อต) จำกัด 30/คั่นเว้นวรรค
- **checkbox กลม หลังเลขแทร็ค** ทุกแถวที่**มี**เลขแทร็ค · แถวไม่มีแทร็ค = ไม่มี checkbox (ติ๊กไม่ได้)
- **ครบ 30 → checkbox ที่เหลือจางลง กดไม่ได้** (ต้องปลดออกก่อนถึงติ๊กเพิ่ม) + แสดง badge **"เลือกครบ 30 แล้ว"** ตรงแถบปุ่ม
- **แถบเครื่องมือที่หัวคอลัมน์เลขแทร็ค** (โผล่เมื่อติ๊ก ≥1): ปุ่ม `[⧉ คัดลอก N]` (N=จำนวนเลือก อัปเดต realtime) + ปุ่ม `[✕]` ล้างการเลือก · ไม่มีติ๊ก = แถบซ่อน หัวคอลัมน์ปกติ
- **คัดลอก** → เลขแทร็คทั้งหมด**คั่นด้วยเว้นวรรค 1 ครั้ง** ลง clipboard + feedback สั้น ("คัดลอกแล้ว ✓") · ลำดับ = ตามที่เห็นในตาราง (เก่า→ใหม่ บนลงล่าง)
- **เปลี่ยนเดือน/กรอง/ค้นหา → ล้างการเลือกทิ้ง** เริ่มใหม่

## ปรับเพิ่มตอน build Stage 1 (2026-08-31, boss สั่งระหว่างลองใช้จริง)
- **คอลัมน์ "ช่องทางชำระ"** (payment_method) เพิ่มก่อนคอลัมน์ยอดขาย · แสดง **COD** ย่อจาก "เก็บเงินปลายทาง" (ค่าใน DB คงเดิม, map ตอนแสดง — ทั้งเซลล์/ฟิลเตอร์/chip) · **ชิดขวา**
- **Layout = full-height app shell (boss เลือก แทน sticky):** body สูง 100vh overflow hidden · top bar + การ์ด KPI อยู่กับที่ (flex:none) · ตารางอยู่ในการ์ดที่ยืดเต็มพื้นที่เหลือ (`.card` flex:1) · **`#tableWrap` overflow:auto = ตารางมีสกรอลล์ของตัวเอง (ขึ้นลง+ซ้ายขวา)** หน้าเพจไม่เลื่อน · หัวตาราง `thead th` sticky top:0 ภายใน tableWrap (ติดบนตอนเลื่อนตาราง) · `table{border-collapse:separate;border-spacing:0}` (กัน sticky th bleed) · **ไม่ใช้ sticky top-bar/kpi + JS offset แล้ว** (ลบทิ้ง)
- **กราฟแท่ง KPI: วันที่ไม่มีข้อมูล = ไม่มีแท่ง** (เหมือนวันอนาคต) — เดิมโชว์ขีดเล็ก min-height, แก้ให้ value 0 = แท่งว่าง
- bug fix: ปุ่ม ✕ ของแถบก๊อปแทร็ค ไม่ซ่อน (CSS `.copybar{display:flex}` override `[hidden]`) → เพิ่ม `.copybar[hidden]{display:none}` — บทเรียน: element ที่ตั้ง display ใน author CSS ต้องมีกฎ `[hidden]` คู่เสมอ
- **เอา subtitle (รวมทุกแบรนด์·เรียง·กรอง·ซูม) ออก** · ย้ายชื่อ "ออเดอร์ — <เดือน>" ไปเป็น breadcrumb บน header (Face Advance / ออเดอร์ — สิงหาคม 2026, เปลี่ยนตามเดือน) — ได้พื้นที่ตารางเพิ่ม
